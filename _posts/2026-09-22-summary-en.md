### [Xiaomi releases open-weight MiMo-V2.6 family with Flash and Pro variants](https://mimo.xiaomi.com/mimo-v2-6) ⭐️ 8.0/10

Xiaomi&\#x27;s MiMo team has released and open-sourced MiMo-V2.6, a mixture-of-experts family with community-verified Hugging Face checkpoints for a Flash variant \(309B total / 15B active parameters\) and a flagship Pro variant \(1.02T total / 42B active parameters\), under the XiaomiMiMo organization. The team describes both as natively omni-modal models aimed at agentic tasks including coding, computer use, 3D scenes, and audiovisual content creation, and says a high-throughput Pro-UltraSpeed variant is rolling out gradually with a claimed up-to-20x output speed increase at comparable quality. The release is unusually transparent for its scale, pairing the weights with a real-time reinforcement-learning training dashboard, a detailed technical report, Qwen models distilled from MiMo training trajectories, roughly 7,000 diverse training environments, and the team&\#x27;s full RL framework. MiMo lead Luo Fuli&\#x27;s claims that this was among the largest single RL training runs by compute for an open-model team and that MiMo-V2.6 now ranks first among open models are vendor statements, not independently verified results.

hackernews · volf\_ · Sep 21, 20:12 · [Discussion](https://news.ycombinator.com/item?id=49792730)

**「MoE parameter accounting and the &\#x27;-RL&\#x27; naming」** Mixture-of-experts \(MoE\) architecture explains the striking parameter counts in this release: the Hugging Face checkpoints carry 309B total parameters for Flash and 1.02T for Pro, but only 15B and 42B respectively activate per token, so inference cost tracks the active figure rather than the full model size. The &\#x27;-RL&\#x27; suffix on checkpoints such as MiMo-V2.6-Flash-RL denotes the reinforcement-learning-trained release; the Flash model card describes it as the efficiency-balanced checkpoint of the series and attaches a technical report titled &\#x27;Scaling Reinforcement Learning Toward Self-Improvement.&\#x27; An earlier Horizon report on the same-day drop noted the release also bundled a 9B Qwen distillation of MiMo training trajectories and an UltraSpeed API latency tier alongside Pro and Flash.

**「Impact」** Developers can act on this immediately: the Flash \(309B total/15B active\) and Pro \(1.02T total/42B active\) checkpoints are downloadable from Hugging Face alongside a web playground and API, with a Pro-UltraSpeed variant rolling out that Xiaomi claims delivers up to 20x faster output at equal quality — a vendor claim, not an independently measured result. Since few teams can self-host the 1.02T-parameter Pro, Flash or the API are the realistic starting points. Beyond inference, Xiaomi also released its RL framework, roughly 7,000 training environments, and Qwen models distilled from MiMo trajectories, so teams can replicate or extend the reinforcement-learning post-training rather than only run the model. Before migrating, treat Xiaomi&\#x27;s claim that MiMo-V2.6 is the top open model as unverified — the predecessor MiMo rated only &\#x27;Tier B usable&\#x27; for coding in an April 2026 independent benchmark — and re-benchmark against your own workloads.

**「Community reaction」** The Hacker News discussion \(275 comments, 534 points\) centered on the release&\#x27;s unusual openness: one commenter called the real-time RL training dashboard an exceptional learning and teaching tool and praised the technical report&\#x27;s methodological detail, while Simon Willison published sample pelican SVG outputs generated by both the Flash and Pro variants. Another commenter argued that Chinese open-weight models have become more exciting than American ones largely on affordability, an individual sentiment rather than a measured assessment of model quality.

### [Cloudflare&\#x27;s Python Workers reach general availability](https://blog.cloudflare.com/python-workers-ga/) ⭐️ 8.0/10

Cloudflare&\#x27;s Python Workers — the ability to run Python on its server-side edge Workers platform — have moved from a two-year preview to general availability, which Cloudflare frames as Python becoming &quot;a first-class, fully supported language on the Cloudflare Developer Platform.&quot; The implementation runs Python compiled to WebAssembly via the Pyodide/Emscripten toolchain, including JSPI support, and Cloudflare says it contributed upstream so Python HTTP clients can route requests through the JavaScript fetch API in WebAssembly environments. A urllib3 maintainer in the discussion confirmed that merged Pyodide/Emscripten and later JSPI contributions to urllib3 are what made Requests work in this environment, and packaging for Python-on-WebAssembly is being standardized through PEP 783.

hackernews · torutofu · Sep 21, 13:38 · [Discussion](https://news.ycombinator.com/item?id=49787142)

**「Background」** Cloudflare&\#x27;s Workers platform executes code on its edge network using a JavaScript/WebAssembly runtime, and the company first offered Python support there as a public preview roughly two years before this release. Python Workers work by compiling CPython to WebAssembly through Pyodide/Emscripten tooling, which required upstream library support — notably Pyodide/Emscripten and JavaScript Promise Integration \(JSPI\) support merged into urllib3 a few years ago — so that Python HTTP clients such as Requests can route traffic through the platform&\#x27;s JavaScript fetch API. The underlying packaging approach has since been formalized in PEP 783, which standardizes the PyEmscripten platform for running Python on WebAssembly-based runtimes.

**「Impact」** Python developers can now build production Workers in a fully supported language rather than a preview-tier feature. Because the code runs compiled to WebAssembly, packages must be compatible with Pyodide/Emscripten builds — maintainers of libraries intended for Workers should expect to carry or review WebAssembly-specific code paths, as urllib3 does — and PEP 783 offers an emerging packaging standard for this environment.

**「Community discussion」** urllib3 maintainer illia-v clarified that the Pyodide/Emscripten and later JSPI support enabling this came from large upstream contributions merged years ago, with funding going to the external contributor who implemented the work rather than the maintainers, who reviewed the changes. Syrus Akbary of competing platform Wasmer praised the progress since the original launch two years ago and highlighted PEP 783&\#x27;s standardization of PyEmscripten, while noting some architectural concerns remain, and another commenter compared the move to Google App Engine launching with Python 2.5 support in 2008.

### [Colin Breck essay argues LLM writing cannot carry the author&\#x27;s meaning](https://blog.colinbreck.com/i-dont-want-to-read-what-you-didnt-write/) ⭐️ 7.0/10

Colin Breck published an essay, &quot;I don&\#x27;t want to read what you didn&\#x27;t write,&quot; arguing that delegating writing to large language models undermines communication because meaning must originate with the author rather than be reconstructed by a tool. The piece is an opinion argument rather than a study or measured result, and it drew a substantial Hacker News discussion on September 21, 2026, reaching 242 points with 94 comments. The debate centered on AI-generated prose, the reviewer burden of LLM-written pull-request descriptions, and commenters&\#x27; claims about declining LLM writing quality, making it directly relevant to engineers who use LLMs to draft documentation and code-review text.

hackernews · mooreds · Sep 21, 22:30 · [Discussion](https://news.ycombinator.com/item?id=49794330)

**「Background」** Breck&\#x27;s essay builds on reader research, highlighted by software engineer Bryan Cantrill in his essay &quot;The revolt of the reader,&quot; finding that when people believe an article is AI-assisted or AI-authored, 78% stop reading it and 71% avoid the author in the future — Cantrill describes readers pulling an &quot;LLM-triggered ejection handle&quot; to bail out mid-sentence. This argument lands as LLM-generated text becomes routine in day-to-day developer communication such as pull-request descriptions, where reviewers are asked to trust words their colleagues did not actually write.

**「Review burden for engineering teams」** For software teams, the concrete consequence is a heavier review-communication burden: as one Hacker News commenter reported, LLM-generated pull-request descriptions now run to pages of justification and risk analysis for a 20-line change, leaving reviewers unable to read it all yet uncomfortable approving text they have not vetted. That dynamic pushes developers toward a practical action — write concise descriptions themselves or get the team to set explicit limits on how much generated text belongs in a review. The essay&\#x27;s cited survey reinforces the stakes, finding that 98% of respondents preferred the author&\#x27;s own writing, flaws and all, over an AI rewrite, so substituting generated prose risks eroding the reader trust that technical communication depends on.

**「Community discussion」** Many commenters supported the essay&\#x27;s premise: one framed writing as an information transfer an LLM cannot reconstruct from partial input, and another described rejecting pull requests padded with pages of AI-generated justification that shifts review risk back onto the reader. Dissent came from a commenter who said AI text is unobjectionable for technical writing they scan for key facts, while another argued, citing user reactions on Reddit, that LLM writing quality has dropped rather than plateaued.

A widely shared Science article reports that NASA&\#x27;s Mars Sample Return mission has been cancelled, ending the agency&\#x27;s long-planned effort to bring Martian rock samples back to Earth. Commenters citing the report describe an architecture that had escalated to roughly $8–11 billion, with samples potentially not reaching Earth until around 2040, and say NASA had already concluded the design was unworkable before the agency&\#x27;s current administrator took over. Several commenters frame the cancellation against China&\#x27;s Tianwen-3 mission, which they describe as a competing Mars sample return effort scheduled to launch in 2028. The figures and program details cited here come from the Hacker News discussion; the article text itself was not available for verification.

hackernews · Muhammad523 · Sep 21, 19:14 · [Discussion](https://news.ycombinator.com/item?id=49791939)

**「Background」** NASA&\#x27;s Perseverance rover has been collecting and storing Martian samples since its arrival in 2021, but the samples were always meant to come home via a separate mission that would collect them, launch them from Mars, and transfer them to another spacecraft for the journey to Earth. That architecture had grown into an estimated $8–11 billion program that would not have returned samples until around 2040, while China&\#x27;s competing Tianwen-3 mission, slated to launch in 2028, aims to deliver Mars samples by 2031. Reporting on the decision suggests it also reflects a shift in U.S. priorities toward human space exploration ambitions.

**「China poised to claim first Mars samples」** For US planetary scientists, the cancellation removes the only funded NASA pathway to physically studying Martian material on Earth, and shifts the first-return milestone to China&\#x27;s Tianwen-3 mission, which is dedicated to Mars sample return and is scheduled to launch as early as 2028 on two Long March 5 rockets — one carrying the lander and ascent vehicle, the other a Mars orbiter. Researchers who want access to fresh Mars samples may therefore need to pursue collaboration with China&\#x27;s program or await a future US architecture, since Tianwen-3 is now positioned to make China the first country to return samples from Mars.

**「Community reaction」** Commenters split between treating the cancellation as inevitable — &quot;financially unfeasible,&quot; as one put it — and assigning blame: a former contributor to the ExoMars Rosalind Franklin rover, itself delayed from 2018 to a 2028 launch, argued the current geopolitical environment is poor for space exploration and hoped Mars Sample Return would one day be revived, while another said JPL leadership doomed the program by growing it to $11 billion and designing around legacy rockets like the Ariane 64 instead of Starship or New Glenn. One commenter went further, calling the article &quot;self-pity propaganda&quot; from scientists who benefited from the old NASA funding model and arguing NASA had already judged the existing architecture bloated before its new leadership arrived.

The available metadata describes the article&\#x27;s scope and framing but does not include its specific findings, measurements, or recommendations, so the strength of its conclusions cannot be verified from the source alone.

rss · Semianalysis · Sep 21, 18:14

**「Why MoE Changes Inference」** Mixture-of-Experts \(MoE\) is an architecture in which each token activates only a small subset of specialized &quot;expert&quot; sub-networks rather than the full model, allowing frontier models to scale total parameters without a proportional rise in per-token compute. This design has become widespread in frontier models and, as the article notes, did more than increase parameter count — it changed both the structure of serving and the economics of useful inference, shifting hardware bottlenecks toward expert weight storage, routing, and data movement between memory and compute.

**「Why It Matters」** For engineers choosing hardware or serving software for MoE models, the article offers an analytical framing centered on computation versus data movement rather than a product release or benchmark result; its practical value depends on details in the full piece that the summary does not disclose, so readers should evaluate the complete article before acting on it.
